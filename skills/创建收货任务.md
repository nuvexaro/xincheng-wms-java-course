## 1. 现状梳理（调研结论，写代码时会直接依赖）

### 1.1 前端传参方式（已核实）

`WmsReceiveTaskAddModal.vue`：

```ts
await createReceiveTask({orderIds: orderIds.value, ...values});
```

`WmsStockInOrders.api.ts`：

```ts
export const createReceiveTask = (params) => {
  return defHttp.post({url: Api.createReceiveTask, params}, {joinParamsToUrl: true});
}
```

- `orderIds` 是勾选行的 **数组**（`selectedRowKeys`）；
- `joinParamsToUrl: true` 会走 `src/utils/index.ts#setObjToUrlParams`，即 `encodeURIComponent(['a','b'])` → `orderIds=a%2Cb`；
- 所以后端收到的是 **逗号分隔的一个字符串**，与需求描述一致 → 用 `@RequestParam(name="orderIds") String orderIds` 接收（不是 `@RequestBody`）。

### 1.2 表单里除了 orderIds 还传了什么（已核实）

`WmsStockInOrders.data.ts#receiveTaskAdd` 只有一个字段：

```ts
{ label: '执行人', field: 'operator', component: 'ApiSelect', ... dynamicRules: 必填 }
```

即 **`operator` = 用户 id（`sys_user.id`）**，且前端标记为必填。
所以 `add` 方法签名是 `add(orderIds, operator)`。

### 1.3 涉及的表（来自 `db/xingchenwms-20251114.sql`）

- `wms_stock_in_orders` —— 入库单主表，状态字段 `status`
- `wms_stock_in_order_items` —— 入库单明细，`order_id` / `product_id` / `expected_quantity` / `status`
- `wms_tasks` —— 任务表，收货任务关键字段：
  `task_number` / `task_type` / `task_status` / `product_id` / `quantity` / `completed_quantity` /
  `operator` / `stock_in_order_id` / `stock_in_order_item_id` / `target_warehouse_id`

**从生产数据里反推出的收货任务字段取值**（样例 `db/xingchenwms-20251114.sql:16212`）：

```
TSK2025071900024, RECEIVING_TASK, COMPLETED, product_id=1911625737452503042, quantity=100,
completed_quantity=100, source_location_code=NULL, target_location_code=NULL,
source_container_code=NULL, target_container_code=NULL, operator=NULL,
stock_in_order_id=1946502359173586945, stock_in_order_item_id=1946502481626292226,
target_warehouse_id=1910288755375820801
```

结论：
- `target_warehouse_id` = 入库单的 `warehouse_id`（样例中两者一致）；
- 收货任务的 `quantity` = 明细的 `expected_quantity`（采购数量）；
- `source_*` 类字段收货任务留空；
- 样例里 `operator` 是 NULL，但前端现在要求填，所以按需求写入 `operator`。

### 1.4 任务号规则 & 序号来源

样例：`TSK2025071900024`、`TSK2025072000008` —— 就是 `TSK` + `yyyyMMdd` + 5 位当日流水，且**各任务类型（RECEIVING/PUTAWAY/PICKING）共用同一套当日流水**。
需求指定用 **Redis** 生成，用 `INCR` 天然原子，可避免并发重复。

### 1.5 可用的基础设施

- Redis：`org.jeecg.common.util.RedisUtil`（来自 `jeecg-boot-common3`，`jeecg-system-biz` 的 `CasClientController` 已在用），有 `incr(key, delta)` / `expire(key, time)`。
  备选：直接注入 `RedisTemplate<String,Object>`（`SysAnnouncementController` 的写法）。
- 异常：`org.jeecg.common.exception.JeecgBootException`（本项目已有用法，见 `WmsStockInOrdersServiceImpl:56`），全局异常处理器会把它转成 `Result.error(msg)` 返回给前端。
- 空判断：`org.jeecg.common.util.oConvertUtils`。
- `createBy` / `createTime` / `sysOrgCode` 由 jeecg 的 MyBatis-Plus 自动填充，**不用手写**（现有 `saveMain` 也没写）。

### 3.1 `wmstask/util/TaskNumberUtil.java`（任务号生成器）

```java
package org.jeecg.modules.wms.wmstask.util;

import lombok.extern.slf4j.Slf4j;
import org.jeecg.common.util.RedisUtil;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

import java.time.LocalDate;
import java.time.format.DateTimeFormatter;

/**
 * @Description: 任务号生成工具
 *               规则: 前缀 + 年月日 + 5位序号, 例如 TSK2025100600001
 *               序号使用 redis 的 INCR 生成, 原子自增, 保证并发下不重复
 * @Version: V1.0
 */
@Slf4j
@Component
public class TaskNumberUtil {

    /** 日期部分格式: 年月日 */
    private static final DateTimeFormatter DATE_FORMATTER = DateTimeFormatter.ofPattern("yyyyMMdd");
    /** 序号位数 */
    private static final int SEQ_LENGTH = 5;
    /** redis key 前缀, 按天区分, 一天一个 key */
    private static final String KEY_PREFIX = "wms:task:number:";
    /** key 过期时间(秒): 2天, 避免 redis 里 key 无限堆积 */
    private static final long EXPIRE_SECONDS = 2 * 24 * 60 * 60L;

    @Autowired
    private RedisUtil redisUtil;

    /**
     * 生成任务号
     *
     * @param prefix 任务号前缀(收货任务传 "TSK")
     * @return 任务号, 如 TSK2025100600001
     */
    public String generate(String prefix) {
        String date = LocalDate.now().format(DATE_FORMATTER);
        String key = KEY_PREFIX + date;

        // redis INCR 是原子操作, 多线程/多节点并发时序号也不会重复
        long seq = redisUtil.incr(key, 1);
        if (seq == 1) {
            // 当天第一次生成, 设置过期时间(第二天 key 自然消失, 序号重新从 1 开始)
            redisUtil.expire(key, EXPIRE_SECONDS);
        }

        // 序号超过 5 位时不再补零(极端情况: 一天超过 99999 个任务)
        return prefix + date + String.format("%0" + SEQ_LENGTH + "d", seq);
    }
}
```

> 如果 `RedisUtil` 的 `incr` 签名与预期不符，可改成：
> `redisTemplate.opsForValue().increment(key)`（返回 `Long`）。
> 对应地把 `@Autowired RedisUtil` 换成 `@Autowired RedisTemplate<String, Object> redisTemplate`。

### 3.3 `inorder/service/impl/ReceiveTasksServiceImpl.java`（核心业务）

```java
package org.jeecg.modules.wms.inorder.service.impl;

import com.baomidou.mybatisplus.core.conditions.update.LambdaUpdateWrapper;
import org.jeecg.common.exception.JeecgBootException;
import org.jeecg.common.util.oConvertUtils;
import org.jeecg.modules.wms.config.WarehouseDictEnum;
import org.jeecg.modules.wms.inorder.entity.WmsStockInOrderItems;
import org.jeecg.modules.wms.inorder.entity.WmsStockInOrders;
import org.jeecg.modules.wms.inorder.service.IReceiveTasksService;
import org.jeecg.modules.wms.inorder.service.IWmsStockInOrderItemsService;
import org.jeecg.modules.wms.inorder.service.IWmsStockInOrdersService;
import org.jeecg.modules.wms.wmstask.entity.WmsTasks;
import org.jeecg.modules.wms.wmstask.service.IWmsTasksService;
import org.jeecg.modules.wms.wmstask.util.TaskNumberUtil;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.ArrayList;
import java.util.List;

/**
 * @Description: 收货任务
 * @Version: V1.0
 */
@Service
public class ReceiveTasksServiceImpl implements IReceiveTasksService {

    /** 任务号前缀 */
    private static final String TASK_NUMBER_PREFIX = "TSK";

    @Autowired
    private IWmsStockInOrdersService wmsStockInOrdersService;
    @Autowired
    private IWmsStockInOrderItemsService wmsStockInOrderItemsService;
    @Autowired
    private IWmsTasksService wmsTasksService;
    @Autowired
    private TaskNumberUtil taskNumberUtil;

    @Override
    @Transactional(rollbackFor = Exception.class)
    public void createReceiveTasks(String orderIds, String operator) {

        //1.必填字段非空校验
        if (oConvertUtils.isEmpty(orderIds)) {
            throw new JeecgBootException("请选择需要创建收货任务的入库单");
        }

        //2.业务处理: 入库单id 是逗号分割的, 切割成数组
        String[] orderIdArray = orderIds.split(",");

        //2.1 遍历入库单
        for (String orderId : orderIdArray) {
            if (oConvertUtils.isEmpty(orderId)) {
                continue;
            }
            orderId = orderId.trim();

            //2.1.1 查询入库单, 非空判断 + 状态判断(只有"审核通过"的入库单才能创建收货任务)
            WmsStockInOrders order = wmsStockInOrdersService.getById(orderId);
            if (order == null) {
                throw new JeecgBootException("入库单不存在: " + orderId);
            }
            if (!WarehouseDictEnum.INBOUND_APPROVED.getCode().equals(order.getStatus())) {
                throw new JeecgBootException("入库单" + order.getOrderNumber() + "不是审核通过状态, 不能创建收货任务");
            }

            //2.1.4 根据入库单明细创建收货任务: 有几条明细就创建几条任务
            List<WmsStockInOrderItems> itemList = wmsStockInOrderItemsService.selectByMainId(orderId);
            if (itemList == null || itemList.isEmpty()) {
                throw new JeecgBootException("入库单" + order.getOrderNumber() + "没有入库明细, 不能创建收货任务");
            }

            List<WmsTasks> taskList = new ArrayList<>();
            for (WmsStockInOrderItems item : itemList) {
                WmsTasks task = new WmsTasks();
                //任务号: TSK + 年月日 + 5位序号(redis 生成)
                task.setTaskNumber(taskNumberUtil.generate(TASK_NUMBER_PREFIX));
                //任务类型: 收货任务
                task.setTaskType(WarehouseDictEnum.TASK_TYPE_RECEIVING.getCode());
                //任务状态: 已创建
                task.setTaskStatus(WarehouseDictEnum.TASK_STATUS_CREATED.getCode());
                //商品
                task.setProductId(item.getProductId());
                //数量 = 明细的采购数量
                task.setQuantity(item.getExpectedQuantity());
                //完成数量初始为 0
                task.setCompletedQuantity(0);
                //执行人
                task.setOperator(operator);
                //来源单据: 入库单 + 入库明细
                task.setStockInOrderId(order.getId());
                task.setStockInOrderItemId(item.getId());
                //目的仓库 = 入库单的仓库
                task.setTargetWarehouseId(order.getWarehouseId());
                taskList.add(task);
            }
            //批量添加收货任务
            wmsTasksService.saveBatch(taskList);

            //2.1.2 更新入库单状态为"收货中"
            WmsStockInOrders updateOrder = new WmsStockInOrders();
            updateOrder.setId(order.getId());
            updateOrder.setStatus(WarehouseDictEnum.INBOUND_RECEIVING.getCode());
            wmsStockInOrdersService.updateById(updateOrder);

            //2.1.3 更新该入库单下所有明细状态为"收货中"
            wmsStockInOrderItemsService.update(new LambdaUpdateWrapper<WmsStockInOrderItems>()
                    .eq(WmsStockInOrderItems::getOrderId, orderId)
                    .set(WmsStockInOrderItems::getStatus, WarehouseDictEnum.INBOUND_DETAIL_RECEIVING.getCode()));
        }
    }
}
```

## 4. 状态流转（本功能改动的部分）

```
入库单 wms_stock_in_orders :      APPROVED(审核通过)  ──►  RECEIVING(收货中)
入库单明细 wms_stock_in_order_items:  (审核通过时的状态)  ──►  RECEIVING(收货中)
新增 wms_tasks             :      task_type=RECEIVING_TASK, task_status=CREATED(已创建)
```

---

## 5. 关键设计说明

1. **事务边界**：整个 `createReceiveTasks` 加 `@Transactional(rollbackFor = Exception.class)`。多个入库单里只要有一个状态不对，之前的操作全部回滚（**这是一个待确认点，见问题 ⑨**）。
2. **批量插入**：用 MyBatis-Plus 的 `saveBatch`，不是循环 `insert`。
3. **状态更新用"只更新状态"的写法**：`updateById` 只更新非 null 字段，不会误改其它列；明细用 `LambdaUpdateWrapper` 一条 SQL 更新整单明细。
4. **任务号并发安全**：`redis INCR` 原子自增 + 按天分 key + 2 天过期；同一天所有任务类型共用一个数组（与生产数据一致）。
5. **异常处理**：统一抛 `JeecgBootException`，由 jeecg 全局异常处理器转成 `Result.error(msg)`，前端 `createMessage` 能直接弹出提示。

## 6. 自测步骤（实现后按这个走一遍）

1. 数据库里准备一个 `status='APPROVED'` 的入库单，带 2~3 条明细。
2. 前端勾选该入库单 → 「创建收货任务」→ 选执行人 → 确定。
3. 校验：
   - `wms_tasks` 新增 N 条（N = 明细数），`task_number` 形如 `TSK2026100600001` 且连续；
   - `wms_tasks.task_type='RECEIVING_TASK'`、`task_status='CREATED'`、`quantity` = 明细的 `expected_quantity`、`target_warehouse_id` = 入库单的 `warehouse_id`；
   - 入库单 `status='RECEIVING'`；
   - 该入库单所有明细 `status='RECEIVING'`。
4. 异常分支：传一个 `status='SUBMITTED'` 的入库单 → 前端提示"…不是审核通过状态…"，且数据库无任何变化。
5. 并发分支：同时点两次，任务号不重复。
